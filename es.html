Cómo funciona

Tres pasos. Tú mantienes el control.

  1. 01

    Conecta

    Clona el repo, ejecuta init, pon una contraseña de aplicación o token OAuth en CYM_PASSWORD o en un password_file local y ejecuta doctor.

  2. 02

    Revisa

    scan lee solo cabeceras y report muestra lo que encontró. plan escribe un plan.json revisable; el correo protegido se queda fuera.

  3. 03

    Limpia

    apply mueve un lote pequeño. journal muestra la ejecución y undo la restaura. La baja es aparte e irreversible.

La CLI

Un conjunto pequeño de comandos.

Python 3.11+. Sin dependencias. Cada comando es explícito y revisable.

doctor

Inicia sesión, comprueba capacidades y encuentra Trash, Junk y Archive.

scan

Guarda cabeceras y clasifica el correo. Sin cuerpos ni adjuntos.

report

Resume remitentes, categorías y objetivos de baja.

plan

Escribe plan.json con UIDs y destinos exactos.

apply

Mueve un lote revisado. Usa --limit en la primera pasada.

journal

Muestra ejecuciones, UIDs movidos y el comando de undo.

undo

Restaura una ejecución tras verificar Message-ID o X-GM-MSGID.

unsubscribe

Envía bajas por separado. Prueba al final, con --limit 1.

folders

Lista o crea carpetas de correo.

unsubs

Muestra el historial de bajas.

rules

Exporta XML de Gmail o un script Sieve para revisar.

Seguridad

Seguro por diseño. Aburrido a propósito.

Sin borrado permanente

Los movimientos copian primero y usan UID EXPUNGE. Sin expunge general. Trash nunca se vacía.

Solo cabeceras

El escaneo lee remitente, asunto, fecha, flags y cabeceras de baja. Los cuerpos y adjuntos nunca salen del servidor.

El correo protegido se queda

Bancos, facturas, viajes, médico, gobierno, personal, destacado, respondido y reciente nunca se mueven automáticamente.

Undo de cada movimiento

El journal guarda COPYUID y Message-ID. Un comando restaura una ejecución. La baja es el único paso irreversible.

Si el servidor no tiene UIDPLUS ni MOVE, los movimientos se rechazan. Lee las reglas de seguridad ↗

FAQ

Respuestas cortas.

¿Borra correo?

No. Mueve a carpetas, etiquetas, Junk, Trash o archivo. Nunca vacía Trash, nunca hace un expunge general y no tiene un comando de “borrar para siempre”.

¿Lee mi correo?

No. Lee solo cabeceras: remitente, asunto, fecha, tamaño, flags y cabeceras de baja. Los cuerpos y adjuntos nunca se descargan.

¿Tengo que ser técnico?

Necesitas Python 3.11+ y una terminal. Un agente puede ejecutar la CLI por ti: pega PROMPT.es.md y sigue el plan. La CLI también se puede usar directamente.

¿Funciona con mi proveedor?

Gmail, Outlook/Microsoft 365, Yahoo, iCloud, Fastmail, Proton Bridge y cualquier servidor IMAP con UIDPLUS o MOVE. Outlook necesita un token OAuth2; la CLI no lo renueva.

¿Cuál es la primera pasada?

Usa scan --days 90, revisa el informe y genera el plan. Aplica como máximo cinco movimientos con --limit 5, revisa journal y ejecuta undo antes de probar la baja.
