How it works

Nothing changes until you approve a plan.

  1. 01

    Connect locally

    Open the skill in your agent, or use the app. Choose your provider and enter your credential. It tests the connection before anything else.

  2. 02

    Scan and review

    The skill or app reads header metadata only: sender, subject, date, size and flags. It shows categories, protected mail, destinations and unsubscribe targets. Nothing changes yet.

  3. 03

    Move a small batch

    Apply a few moves. The journal records the run and Undo restores it. Review the result before handling unsubscribe separately.

Safety

Review first. Undo the moves.

No permanent deletion

There is no permanent-delete command. CleanYourMail never empties Trash or Junk and never runs a mailbox-wide expunge.

Headers only

It reads sender, subject, date, size, flags and unsubscribe headers, and stores that metadata locally. It never downloads bodies or attachments.

Protected mail stays put

Personal, transactional, security, banking, invoice, travel, medical, government, legal, starred, answered and recent mail is excluded from automatic moves and unsubscribe requests.

Review, move, undo

scan, report and plan change nothing. Review the plan, start with a small move, and use the journal and undo to restore that run. Unsubscribe is separate and irreversible.

Runs locally: no hosted CleanYourMail service, no account, no telemetry. Inspect the code, the safety model and the tests.

FAQ

Questions before you connect.

Does it delete email?

No. It has no permanent-delete command, never empties Trash or Junk, and never runs a mailbox-wide expunge. Moves and archives are journaled; unsubscribe requests are not reversible.

What does it read?

Headers only: sender, subject, date, size, flags and unsubscribe headers. It never downloads bodies or attachments. The local cache stores metadata, not message bodies.

Do I need to be technical?

The app is the simple path. The skill, the main product, needs a coding agent with shell access. The CLI is for developers who prefer the terminal. All three use the same plan and undo model.

Does it work with my provider?

Gmail, Outlook/Microsoft 365, Yahoo, iCloud, Fastmail, Proton Bridge and compatible custom IMAP servers. Gmail needs an App Password with 2-Step Verification; Microsoft 365 sign-in requires tenant admin consent; personal Outlook.com requires a verified publisher (pending); Proton needs Bridge. Custom IMAP moves require UIDPLUS or MOVE. Provider or tenant policies may block access; the tool does not bypass them.

What happens if something goes wrong?

Stop and inspect the error. The skill, the CLI and the app re-check the plan before applying it and record each run. Use the printed undo command to restore that run’s moves. If a message cannot be found, the journal remains for manual recovery. Unsubscribe requests cannot be undone.

Is it really free?

Yes. MIT-licensed, no paid tier, no CleanYourMail account and no telemetry. You provide your computer, Python installation and mail-provider access.
